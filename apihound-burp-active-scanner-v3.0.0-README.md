# APIHound 3.0 — Burp Suite Automated Active API Scanner

APIHound 3.0 converts the earlier Python/Jython APIHound/API Gunner prototype into a native Java extension for Burp Suite's Montoya API. It registers passive, request-level active, and per-insertion-point active scan checks, adds an APIHound settings/import tab, and can optionally auto-queue unique in-scope Proxy traffic into a Burp active audit.

> Use only on systems for which you have explicit authorization. Active scanning sends modified HTTP requests and can change application state when the relevant opt-in controls are enabled.

## Install the prebuilt extension

1. Use a current Burp Suite Professional release.
2. Open **Extensions → Installed → Add**.
3. Select **Java** as the extension type.
4. Choose `dist/apihound-burp-active-scanner-v3.0.0.jar`.
5. Confirm that the **APIHound** top-level tab appears and review **Extensions → Output/Errors**.
6. Define the target in Burp scope before scanning.

Burp Scanner and programmatic active audits are Professional-only. The extension UI may load in another edition, but active scanner registration and audit launch require an edition exposing the Scanner APIs.

## Automated operating modes

### 1. Standard Burp audit integration

The extension registers its scan checks with Burp. Start an audit from Burp's Dashboard, Target, Proxy history, Repeater, or other normal Scanner workflow. Burp invokes APIHound automatically:

- once per request for authentication, JWT, CORS, GraphQL, inventory, method-override, mass-assignment, and controlled rate-limit logic;
- once per insertion point for SQLi, NoSQLi, command injection, SSTI, reflection, BOLA/IDOR, SSRF indicators, type confusion, and optional traversal;
- passively for sensitive response fields, backend errors, JWT configuration, cookie attributes, CORS inconsistencies, HSTS, version disclosure, and observed GraphQL introspection.

### 2. APIHound import-and-scan

The **APIHound → Import and scan** tab can start an audit directly from:

- a raw HTTP request copied from Burp or saved in a file (`sqlmap -r` style);
- a normal Postman collection v2.x;
- one combined JSON document containing the Postman collection/template and environment values.

The importer resolves `{{variable}}` and `${variable}` placeholders locally. It supports inherited collection/folder/request authentication, bearer/basic/header API-key/OAuth2 metadata, raw bodies, URL-encoded bodies, text form-data, and GraphQL bodies. Postman scripts are not executed and file upload parts are skipped.

### 3. Fully automatic Proxy mode — opt-in

Enable **Auto-queue unique in-scope Proxy traffic** and apply the settings. APIHound then places each unique eligible Proxy request/response into one active-audit task. Duplicates are suppressed using method, URL, and body fingerprinting. Scanner-generated traffic is not re-queued.

This mode is deliberately disabled by default. It uses Burp's active audit configuration as well as APIHound checks, so enable it only after confirming scope, session handling, resource pools, and authorization.

## Authentication/header handling

Every active mutation starts from Burp's captured request. Therefore the original method, URL, request body, Authorization header, Cookie header, API keys, request IDs, tenant/sponsor headers, and other custom headers are retained unless the individual check intentionally changes one of them.

Authentication bypass tests intentionally remove only these common authentication/session headers:

- `Authorization`
- `Cookie`
- `X-API-Key`
- `API-Key`
- `X-Auth-Token`
- `X-Access-Token`

The optional importer override is authoritative only for those same authentication/session header names. Unrelated headers remain unchanged.

## Safe defaults

The default configuration is conservative:

- scan only Burp in-scope requests;
- do not auto-queue Proxy traffic;
- do not replay POST, PUT, PATCH, or DELETE requests;
- skip login, token, password, OTP, SPIN, verification, redemption, deposit, transfer, and payment-like paths;
- disable mass-assignment, controlled rate-limit, and path-traversal probes;
- cap APIHound insertion-point requests at 10;
- apply a 125 ms global delay between requests generated by APIHound;
- never use Collaborator, cloud metadata addresses, external callbacks, AI services, telemetry, or third-party APIs.

These controls apply to APIHound's custom checks. Burp's own scan configuration and resource pool must also be reviewed because an imported or auto-queued audit invokes Burp's active-audit engine.

## Coverage and evidence model

| Area | Automated behavior | Default |
|---|---|---:|
| Authentication | Removes auth/session headers only after a successful authenticated baseline; reports only when a user-specific response remains materially equivalent | On |
| JWT validation | Tests `alg:none`, empty signature, and corrupted signature only after proving the endpoint rejects a missing credential | On |
| CORS | Sends an invalid Origin and looks for credentialed origin reflection | On |
| BOLA / IDOR | Mutates ID-like insertion points and uses status, body-shape, and similarity differentials | On for safe methods |
| SQL injection | Sends a compact metacharacter payload and requires a new database error signature | On |
| NoSQL injection | Sends an operator-shaped value and requires new NoSQL errors or a meaningful authorization transition | On |
| Command injection | Uses a randomized `printf` marker and requires the calculated marker in the response | On |
| SSTI | Uses randomized arithmetic and requires the calculated result to appear newly | On |
| Reflection | Uses a randomized HTML/attribute marker and reports unencoded reflection | On |
| SSRF indicator | Uses an unreachable loopback URL and looks for a new connection/error indicator; no OAST callback | On |
| Type confusion | Replaces an insertion point with an array-like value and looks for a new type/verbose error | On |
| GraphQL | Sends a minimal schema query to GraphQL-like endpoints and analyzes the returned schema shape | On |
| Inventory | Probes one adjacent numeric API version for safe methods | On |
| Method override | Adds `X-HTTP-Method-Override: GET` to an allowed state-changing replay | State-changing opt-in |
| Mass assignment | Adds a canary property to a JSON object and checks whether it is returned/accepted | Extra-authorization opt-in |
| Rate limiting | Sends a controlled six-request sample and reports only an absence of observable throttling, as tentative evidence | Extra-authorization opt-in |
| Path traversal | Sends a local-file path and requires recognizable local-file content | Extra-authorization opt-in |

Automated findings include the baseline and test request/response evidence in Burp. Differential checks reduce noise, but BOLA, business-logic, rate-limit, CORS, and error-based findings still require manual validation.

## Build from source

The project targets Java 17 bytecode, which is within Burp's supported Java 21-or-lower range, and uses Montoya API `2026.7` as a compile-only/provided dependency.

### Gradle

```bash
gradle clean jar
```

Output: `build/libs/apihound-burp-active-scanner-v3.0.0.jar`

### Maven

```bash
mvn clean package
```

Output: `target/apihound-burp-active-scanner-v3.0.0.jar`

### JDK-only verified-dependency build

Linux/macOS:

```bash
./scripts/build-local.sh
```

Windows PowerShell:

```powershell
.\scripts\build-local.ps1
```

The JDK-only scripts download the official Montoya `2026.7` release JAR if needed and verify its published SHA-256 before compilation. You can instead set `MONTOYA_JAR` to an already-downloaded official JAR.

## Verify the prebuilt JAR

```bash
./scripts/verify-jar.sh
```

The verifier checks the extension entry point, service registration, Java 17 class version, and confirms that Montoya API classes were not bundled.

After `build-local.sh` has downloaded the verified Montoya dependency, run the portable smoke test with:

```bash
./scripts/run-smoke-tests.sh
```

## Current limitations

- APIHound does not execute Postman pre-request or test scripts.
- File/multipart binary parts are skipped by the collection importer.
- The extension does not crawl an application or parse OpenAPI specifications; use Burp's crawl/API scan workflow, normal Proxy traffic, raw request import, or Postman import to supply requests.
- It does not perform credential stuffing, large-payload denial-of-service probes, cloud-metadata SSRF, blind/OAST checks, destructive deletion, or unrestricted concurrency.
- The conservative BOLA mutation is not a substitute for two authenticated user contexts. Confirm object ownership manually before reporting.
- Authentication refresh is delegated to Burp session handling, macros, and the captured/imported headers.
